# v4 plan: Home Assistant calendar, Ready for Pickup and Cart actions

Agreed in the design session on 2026-10-28. Vocabulary lives in `GLOSSARY.md`, hard-to-reverse decisions in `docs/adr/`. No new Bilka endpoints: everything builds on what v1 to v3 already read and write.

## Scope

- Home Assistant gains a calendar entity, a Ready for Pickup binary sensor and two actions, `bilkatogo.add_to_cart` and `bilkatogo.search`.
- The library gains `NoPickupPointError`. The CLI is otherwise unchanged.
- Built for anyone installing from HACS, not only the maintainer's household: nothing needs extra setup.
- ADR 0005 holds: nothing past the Cart.
- Out: a todo entity backed by the Cart, free-text matching of a name to a Product, set and remove Cart actions, a Cart sensor, the order change deadline, Pickup Slot availability, reordering into the Cart, Offer watch, spending history, favourites. The open `needs-info` tickets #27 to #29 are unchanged.

## Calendar

- One calendar entity per config entry.
- Events come from the Orders the coordinator already fetches on every poll (`get_orders(limit=CURRENT_ORDER_SCAN_LIMIT)`, 20 Orders), so the calendar costs no extra request. The coordinator keeps that list next to the Current Order instead of dropping it.
- Every Order with a Pickup Slot is an event, upcoming and past, except Cancelled and Sold Out Orders.
- An event spans the Pickup Slot (`starts_at` to `ends_at`, Bilka's time zone).
- Summary: translated "BilkaToGo pickup", or "BilkaToGo delivery" for Home Delivery.
- Location: the Pickup Point's name. Empty for Home Delivery, whose address is personal.
- Description: the Order Number and the Order Status.
- Never the Pickup Code: calendars are synced and shared further than entity states, and the code is already its own sensor.
- The entity's state follows HA's calendar rules: on during an event, `event` is the next or current one.

## Ready for Pickup

- A binary sensor, on while the Current Order's Order Status is Packed, off otherwise: no Current Order, Processing, Received, Picked Up, Not Collected, Cancelled, Sold Out and Unknown.
- Home Delivery follows the same rule: Packed means it is on its way.
- No device class.

## Actions

- Registered once in `async_setup`, not per config entry, as HA requires.
- Both take an optional `config_entry_id`. With one loaded BilkaToGo entry it may be left out; with several it is required and leaving it out raises a translated error naming the problem.
- A `BilkaToGoError` from the library becomes a translated `HomeAssistantError`; invalid credentials start reauth like the coordinator does.

### `bilkatogo.add_to_cart`

- Fields: `article_number` (required), `quantity` (default 1, at least 1).
- Calls `add_to_cart(article_number, quantity)`: adds to what is already in the Cart.
- Response optional: the updated Cart (Cart Lines with Product, Article Number, quantity, Price and line total; Cart total; Deposit, Service Fee, Packaging, Discount; Pickup Point name; Bilka's warnings).
- `CartChangeRejectedError` becomes a translated error carrying Bilka's message.
- No free-text matching: a script searches first and picks a result itself.

### `bilkatogo.search`

- Fields: `query` (required), `limit` (default 10).
- Response only.
- Searches at the Store serving the Cart's Pickup Point; no option to name another.
- Each result: Article Number, name, brand, Price, Unit Price and unit, in stock, Offer (label, Offer Price, Offer Unit Price, end date, limit per customer) and Multibuy Offer, the fields the CLI's `search --json` shows.
- With no Pickup Point in the Cart it raises a translated "choose a Pickup Point on bilkatogo.dk first" error, from `NoPickupPointError`.

## Library

- `NoPickupPointError(BilkaToGoError)`, raised by `search()` when no Pickup Point is named and the Cart has none (today a plain `BilkaToGoError`). The CLI keeps its current message.

## Translations

- Every new name, field, description and error in `strings.json`, `translations/en.json` and `translations/da.json`.

## Testing

- Library: `NoPickupPointError` against the fake backend with a Cart without a Pickup Point.
- Home Assistant (`scripts/ha-test.sh`): calendar events from a list of Orders (Cancelled and Sold Out left out, Home Delivery without location, no Pickup Code); the binary sensor in every Order Status; both actions with one and with several config entries, a rejected change, no Pickup Point, and the response shapes.
- Diagnostics snapshot updated if the coordinator data changes shape.
- Before release the maintainer runs `add_to_cart` once against their own Cart from HA, like the v3 writes.
