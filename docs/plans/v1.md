# v1 plan: bilkatogo library, CLI and Home Assistant integration

Agreed in the design session on 2026-10-26. Vocabulary lives in `CONTEXT.md`, hard-to-reverse decisions in `docs/adr/`.

## Repo and release

- Monorepo `bilkatogo`, layout:
  ```
  pyproject.toml                # bilkatogo, extras [cli], [mcp]
  hacs.json
  src/bilkatogo/                # client, auth, models, cli/ (Typer only here), mcp/ later
  custom_components/bilkatogo/  # thin HA integration
  tests/bilkatogo/              # mirrors src
  tests/custom_components/
  ```
- Lockstep versioning: one `vX.Y.Z` GitHub release publishes `bilkatogo==X.Y.Z` to PyPI, equals `manifest.json` `version` and the Marketplace version (ADR 0001).
- Stack: Python >=3.14, uv with `uv_build` (upper-bounded), httpx in core, Typer (upper-bounded, includes rich) in `[cli]`, ruff (aula rules), ty, pytest + pytest-asyncio. HA tests use a separate uv dependency group `hass` and their own CI job.
- Marketplace-ready from day 1: hassfest and HACS action in CI, `brand/icon.png`, `categories` in the manifest. Submit to `hacs/default` once stable.

## Library

- Login: Gigya `accounts.login` → `accounts.getJWT` (24 h) → `POST api.bilkatogo.dk/api/auth/LoginJWT`, then send `jwt_token` header and `PHPSESSID` cookie. Re-login on 401. Token persisted through a `TokenStorage` ABC (ADR 0002).
- Endpoints (read-only, orders only): `v7/OrderHistory?limit&offset&muah=1&ordertype=dibs,pgw`, `v7/OrderDetails?orderId=`.
- Models are dataclasses with `from_dict()` and `_raw`, like aula.
- Order Status mapping from Bilka Status Codes as in `CONTEXT.md`, raw code kept (ADR 0003).
- Substitution: an order line with `strikethrough: true` and `tagline: "erstattet"`; the Replacement Product is in `children[]`. Order has `stat.has_replacements`.
- Missing Items are not modelled in v1; log order lines with a non-empty `unavailable_reason`.
- Pickup first; `home_delivery` is part of the model.
- CLI: `bilkatogo login`, `orders [--limit]`, `order [id]` (no id = Current Order), `--json` everywhere. Credentials: flag → `BILKATOGO_EMAIL` / `BILKATOGO_PASSWORD` → `~/.config/bilkatogo/config.json` → prompt. Async commands go through an `asyncio.run` wrapper.
- No agent skill in v1.

## Home Assistant integration

- Domain `bilkatogo`. Config flow with email and password, plus reauth.
- Tracks the Current Order. Entities: order status (enum, raw code as attribute), number of Substitutions (list of `{original, replacement, quantity}` as attribute), Pickup Slot start (timestamp), Pickup Code, Pickup Point. Order Number, price and Pickup Slot end as attributes.
- Event `bilkatogo_substitution`, fired once per new Substitution; already-notified ones (Order Number + Original Product) kept in a HA `Store` so restarts do not repeat them.
- Polling: every 60 min; every 5 min from 3 h before Pickup Slot start until Picked Up, Not Collected or Cancelled. Fixed values. OrderDetails only fetched from Packed onwards, stopping once Picked Up.
- Danish and English translations.
